# I18N.md — Arquitectura multiidioma de Apptonomia

Referencia técnica del sistema de internacionalización (`App.i18n`) y receta paso a
paso para añadir un idioma nuevo. Leer junto a `SPEC.md` §3.2b (referencia rápida de
la API) y `CLAUDE.md` (reglas de accesibilidad, que aplican **en todos los idiomas**).

**Estado actual**: español (`es`, por defecto) e inglés (`en`). El sistema está
diseñado para más de dos idiomas, pero hoy tiene varios puntos con lógica binaria
`es`/`en` (formato de números, expresiones horarias, selector de la landing) que
hay que generalizar al añadir un tercero — ver §4.

**Política de idioma**:

- **Interfaz de usuario (UI)**: multiidioma — todos los textos visibles para el
  usuario final existen en cada idioma soportado (`es`, `en`…).
- **Código técnico**: **siempre en inglés** — nombres de variables, funciones,
  objetos JavaScript y, **crucialmente, las claves de `strings.js`** deben ser
  en inglés. Los valores de las claves son el texto traducible (UI), pero la
  clave misma es código técnico y por tanto va en inglés.

  ```js
  // ✅ Correcto — clave en inglés, valores en el idioma correspondiente
  App.i18n.register({
    es: { levelTitle: 'Elige el nivel', cardFaceDown: 'Carta boca abajo' },
    en: { levelTitle: 'Choose a level', cardFaceDown: 'Card face down' }
  });

  // ❌ Incorrecto — clave en español (mezcla código técnico con UI)
  App.i18n.register({
    es: { tituloNiveles: 'Elige el nivel', cartaTapada: 'Carta boca abajo' },
    en: { tituloNiveles: 'Choose a level', cartaTapada: 'Card face down' }
  });
  ```

  Esta distinción permite que `App.i18n.t('levelTitle')` sea legible en el código
  fuente, independientemente del idioma activo.

## 1. Piezas del sistema

```
assets/js/i18n.js        # Núcleo: App.i18n (detección, persistencia, t/pick/apply)
site/strings.js          # Textos ES/EN de la landing
site/index.html           # Selector de idioma (2 botones fijos, no generados)
tools/<slug>/strings.js  # Textos ES/EN de cada actividad
tools/<slug>/data.js     # Datos: algunos indexados por idioma, otros compartidos
tools/<slug>/app.js      # Usa App.i18n.t()/.pick()/.locale() para leer/generar texto
```

### 1.1 `assets/js/i18n.js` — núcleo

```js
var SOPORTADOS = ['es', 'en'];   // idiomas activables
var POR_DEFECTO = 'es';          // fallback si falta una clave o el idioma detectado no está soportado
```

- **Detección** (`detectar()`): recorre `navigator.languages`, se queda con el
  prefijo de 2 letras del primero que esté en `SOPORTADOS`. Si ninguno coincide,
  usa `POR_DEFECTO`.
- **Persistencia** (`locale()` / `setLocale()`): `localStorage['apptonomia:locale']`.
  Si hay un valor guardado y soportado, gana sobre la detección. `setLocale()`
  guarda y **recarga la página** (no hay re-render en caliente).
- **`register(dict)`**: fusiona `{es:{...}, en:{...}}` en el diccionario interno.
  Cada `strings.js` lo llama una vez al cargar. Es un *merge* superficial por clave
  de primer nivel (`core`, `feedback`, y las que registre cada herramienta), así que
  dos `strings.js` distintos no pueden compartir la misma clave de primer nivel sin
  pisarse — cada herramienta usa su propio namespace implícito (sus propias claves).
- **`t(key)`**: busca `key` (con puntos, p. ej. `'nivel.c1'` o `'core.volver'`) en el
  idioma activo. Si no está, cae a `POR_DEFECTO` (español). Si tampoco está,
  devuelve la propia `key` (para detectar claves rotas a simple vista en pantalla).
  Si el valor es un array, lo une con `', '` (pensado para depurar, no para UI).
- **`pick(key)`**: como `t`, pero para claves que son un **array** de variantes
  (p. ej. `feedback.acierto`) — devuelve una al azar. Usado por `feedback.js` para
  los mensajes de ánimo/acierto.
- **`apply(root)`**: aplica `data-i18n` (→ `textContent`) y `data-i18n-aria`
  (→ `aria-label`) a todo el DOM bajo `root` (por defecto `document`). Se ejecuta
  sola en `DOMContentLoaded`. También pone `document.documentElement.lang` y, si
  `<html>` tiene `data-i18n-title="clave"`, fija `document.title = t(clave) + ' | Apptonomia'`.
- **`lang()`**: `'es' → 'es-ES'`, cualquier otro → `'en-US'` (hoy binario — ver §4).
  Lo usa `App.tts.speak()` para elegir la voz de `speechSynthesis`.

### 1.2 Claves comunes (`core.*`, `feedback.*`)

Definidas una vez en `i18n.js`, **no redefinir** en el `strings.js` de cada
herramienta. Todas las subclaves van en inglés (código técnico):

| Clave | ES | EN |
|---|---|---|
| `core.back` | ← Volver | ← Back |
| `core.backToMenu` | Volver al menú | Back to menu |
| `core.playAgain` | Jugar otra vez | Play again |
| `core.next` | Siguiente → | Next → |
| `core.listen` | 🔊 Escuchar | 🔊 Listen |
| `core.listenInstructions` | Escuchar las instrucciones | Listen to the instructions |
| `core.listenText` | Escuchar el texto | Listen to the text |
| `core.loading` | Cargando… | Loading… |
| `core.roundComplete` | ¡Ronda completada! | Round complete! |
| `feedback.success` (array) | ¡Muy bien! / ¡Genial! / … | Well done! / Great! / … |
| `feedback.encourage` (array) | Casi. ¡Inténtalo otra vez! / … | Almost. Try again! / … |

### 1.3 `strings.js` de cada herramienta

Patrón (ver `tools/parejas/strings.js` como referencia de oro):

```js
(function () {
  'use strict';
  App.i18n.register({
    es: { title: '🃏 Parejas', instruction: '...', pairsPerLevel: '{n} parejas', ... },
    en: { title: '🃏 Pairs',   instruction: '...', pairsPerLevel: '{n} pairs',   ... }
  });
})();
```

**Importante**: las claves (`title`, `instruction`, `pairsPerLevel`) son código
técnico y van siempre en inglés, independientemente del idioma de la UI. Los
valores son el texto traducible para el usuario.

- Debe existir siempre la clave `title` (la usa `data-i18n-title` para el `<title>`).
- Placeholders con llaves (`'{n} veces'`) se sustituyen a mano en `app.js` con
  `.replace('{n}', valor)` — **no hay motor de interpolación**; si una clave tiene
  el mismo placeholder repetido dos veces, hay que usar `.replace(/\{n\}/g, valor)`
  (un bug real de este tipo se coló y se corrigió durante la migración de
  `tools/numeros/app.js` — ver `multiplicarHablar`).
- Objetos anidados funcionan como namespaces: `nivel: { c1: '...', c2: '...' }` se
  lee con `t('nivel.c1')`.
- **Nunca** un array cuando se necesita indexar por posición (`t()` uniría el array
  con comas). Para tablas indexadas por número usar un objeto con claves de texto:
  `{ 0: '', 1: 'miles', 2: 'millones' }` y leer con `t('grupoEtq.' + i)`.

### 1.4 Dónde vive el texto: tres patrones de `data.js`

1. **Datos indexados por id, texto en `strings.js`** (recomendado cuando la mayoría
   de campos son estructurales: coordenadas, colores, ids de nivel…). Ejemplo:
   `tools/colorear/data.js` guarda `{ id: 'casa', picto: '🏠', zonas: [...] }` y
   `app.js` busca el nombre con `App.i18n.t('dibujo.' + d.id)`.
2. **`DATA` duplicado completo por idioma** (`{ es: [...], en: [...] }`) cuando casi
   todos los campos son texto o cambian de fondo entre idiomas (números de una
   lectura, palabras de mecanografía). Ejemplo: `tools/adivinanzas/data.js`,
   `tools/keyboard-typing/data.js` (`DATA.lessons`, `DATA.words`, `DATA.placement`,
   `DATA.numpadSteps`). Se accede con `DATA.<campo>[App.i18n.locale()]`.
3. **Datos compartidos sin duplicar**, cuando de verdad no dependen del idioma:
   importes en céntimos (`DATA.llegaUno`/`DATA.cambio` en `numeros`), geometría de
   un teclado físico (`DATA.rows`/`DATA.numpad` en `keyboard-typing` — ver §5 de
   `SPEC.md` sobre por qué el teclado español con Ñ se mantiene igual en inglés).

### 1.5 HTML: atributos `data-i18n*`

```html
<html lang="es" data-i18n-title="title">
...
<h1 data-i18n="title">🃏 Parejas</h1>
<button data-i18n-aria="core.listenInstructions" aria-label="Escuchar las instrucciones">🔊</button>
```

El texto/`aria-label` español queda como contenido por defecto en el HTML (para que
la página tenga sentido incluso si `i18n.js` no cargase) y `apply()` lo sobrescribe
al arrancar. Atributos que `apply()` **no** cubre (hay que fijarlos a mano en
`app.js` al arrancar): `placeholder` de `<textarea>`/`<input>` — ver
`tools/keyboard-typing/app.js`, sección "Arranque".

### 1.6 Orden de carga de scripts (obligatorio)

```html
<script src="../../assets/js/utils.js"></script>
<script src="../../assets/js/i18n.js"></script>
<script src="../../assets/js/tts.js"></script>
<script src="../../assets/js/storage.js"></script>
<script src="../../assets/js/feedback.js"></script>
<script src="strings.js"></script>
<script src="data.js"></script>
<script src="app.js"></script>
```

`i18n.js` antes que `tts.js`/`feedback.js` (ambos leen el idioma activo) y antes de
`strings.js`/`data.js` de la herramienta (que registran/consultan texto).

### 1.7 Selector de idioma (landing)

`site/index.html` tiene **dos botones fijos** (no generados desde `SOPORTADOS`):

```html
<div class="idioma-selector" role="group" aria-label="Elegir idioma">
  <button id="btnIdiomaEs" data-locale="es" aria-pressed="false">🇪🇸 Español</button>
  <button id="btnIdiomaEn" data-locale="en" aria-pressed="false">🇬🇧 English</button>
</div>
```

con JS propio (`pintarSelectorIdioma()`, listeners de `click` → `App.i18n.setLocale(...)`)
en `site/index.html`. Añadir un idioma implica añadir un tercer botón a mano (§5).

## 2. Formato de números, dinero y horas: NO es solo traducción

Estos tres puntos son la parte más delicada del sistema — traducir la palabra sin
tocar el formato produce un número o una hora que se lee mal o directamente falso:

- **Separadores de miles/decimales**: español usa `.` para miles y `,` para
  decimales (`1.234,50`); inglés al revés (`1,234.50`). Ver
  `tools/numeros/app.js` (`separadorMiles()`, `separadorDecimal()`) y
  `tools/monedero/app.js` (línea con `App.i18n.locale() === 'en' ? '.' : ','`).
- **Escala numérica**: el español usa escala larga (1 000 000 000 = "mil millones",
  1 000 000 000 000 = "un billón"); el inglés usa escala corta (10⁹ = "one billion",
  10¹² = "one trillion"). Traducir "billón" por "billion" da un número **mil veces
  menor** del que se quería decir. Ver `tools/numeros/data.js` (`DATA.lecturas`,
  con arrays `es`/`en` completamente distintos en las palabras, no solo traducidos)
  y `DATA.grupoEtq` en `strings.js` (etiquetas de grupo de 3 cifras: español
  necesita `'miles de millones'`/`'billones'` como parches; inglés tiene una
  palabra corta por grupo: `thousand/million/billion/trillion`).
- **Horas**: "y cuarto"/"menos cuarto"/"y media" no son "and a quarter"/"less a
  quarter" en inglés natural — son "quarter past"/"quarter to"/"half past". Ver
  `tools/reloj/strings.js` (`horaEnPunto`, `horaYCuarto`, `horaYMedia`,
  `horaMenosCuarto`) y `tools/reloj/app.js` (`textoHora()`).

**Regla general**: antes de traducir literalmente un texto con un número, una fecha,
una hora o una moneda, comprobar cómo lo diría de verdad un hablante nativo del
idioma destino. Si hace falta, la plantilla puede tener una estructura de frase
distinta por idioma (ver `precioConCentimos`, con `'{euros} y {c} céntimos'` en
español vs. `'{euros} and {c} cents'` en inglés — mismo orden aquí, pero no hay que
asumirlo).

## 3. Contenido cultural (dichos, chistes, adivinanzas, nombres): NO traducir literalmente

Regla igual de estricta que la del §2, pero para texto en vez de números: **un dicho,
un chiste o una adivinanza traducidos palabra por palabra del español dejan de
funcionar en inglés** — el chiste ya no da risa, el dicho no existe como tal, la
adivinanza pierde la rima o el doble sentido en el que se apoyaba. La versión en
cada idioma tiene que ser un contenido **propio de ese idioma**, con la misma
dificultad e intención pedagógica que el original, no una traducción de él.

- **`tools/dichos/`**: los dichos en inglés son modismos ingleses reales
  ("Break the ice", "Piece of cake", "Once in a blue moon"), no la traducción de
  "A quien madruga, Dios le ayuda". Las opciones de respuesta son el significado
  del modismo inglés, no la traducción del significado del dicho español.
- **`tools/comedy-club/`**: los chistes en inglés son juegos de palabras que
  funcionan en inglés ("Why did the bicycle fall over? Because it was two-tired.")
  — un chiste español traducido literalmente ("Jaguar que te pillo") no tiene
  ninguna gracia en inglés porque el juego de palabras no existe en ese idioma.
- **`tools/adivinanzas/`**: las adivinanzas en inglés son acertijos ingleses
  equivalentes (mismo objeto/respuesta cuando es razonable, pero con su propio
  juego de palabras o rima), no la traducción literal del verso español.
- **`tools/la-frase/`**: los nombres de los personajes de las frases de ejemplo
  son nombres propios del idioma (`Emma`, `Jack`, `Grace`, `Grandma`), no los
  nombres españoles traducidos o dejados igual (`María`, `Pedro`).
- **`tools/palabras/`, `tools/categorias/`, `tools/que-falta/`, etc.** (vocabulario
  de objetos cotidianos): aquí sí corresponde la traducción directa palabra a
  palabra (`Perro` → `Dog`) — un perro es un perro en cualquier idioma, no hay
  matiz cultural que preservar. La regla de este apartado es para contenido que
  depende del idioma en sí (modismos, juegos de palabras, rimas, nombres propios),
  no para nombres de objetos.

**Gap real encontrado y corregido** (commit `24168ac`): `tools/entre-amigos/`
tenía `strings.js` con las claves de interfaz correctas, pero nunca se cargó en
`index.html` (sin `<script src="strings.js">`, sin atributos `data-i18n`) ni se
usó desde `app.js` (cero llamadas a `App.i18n`). Cambiar el idioma a inglés dejaba
el menú traducido a medias y las 44 situaciones del juego enteramente en español.
Aquí sí correspondía traducción directa (son situaciones sociales universales, no
modismos), pero el fallo real era que **no se había traducido nada en absoluto** —
un recordatorio de que "existe `strings.js`" no es lo mismo que "está conectado".
Antes de dar por buena una herramienta migrada, comprobar los tres cabos sueltos
que fallaron aquí: `grep -c 'src="strings.js"' tools/<slug>/index.html`,
`grep -c 'data-i18n' tools/<slug>/index.html` y `grep -c 'App.i18n' tools/<slug>/app.js`
— los tres deben dar más de cero.

## 4. Puntos con lógica binaria `es`/`en` (a generalizar al añadir un idioma)

Grep de referencia: `grep -rn "locale() === 'en'" assets/ tools/`. Líneas verificadas
sobre el estado del repo en el commit `86a4129`; si el archivo cambia, volver a
grepear en vez de fiarse del número de línea.

| Archivo:línea | Qué hace | Qué hay que cambiar para un 3er idioma |
|---|---|---|
| `assets/js/i18n.js:17` (`SOPORTADOS`) | `var SOPORTADOS = ['es', 'en'];` | Añadir el código de idioma: `['es', 'en', 'fr']` |
| `assets/js/i18n.js:87` (`lang()`) | `return locale() === 'en' ? 'en-US' : 'es-ES';` | Convertir en un mapa `{es:'es-ES', en:'en-US', fr:'fr-FR'}` con fallback |
| `tools/numeros/app.js:68` (`separadorMiles`) | `App.i18n.locale() === 'en' ? ',' : '.'` | Mapa por idioma (no asumir que un idioma nuevo comparte convención con `es` o con `en`) |
| `tools/numeros/app.js:69` (`separadorDecimal`) | `App.i18n.locale() === 'en' ? '.' : ','` | Igual que arriba |
| `tools/numeros/app.js:234` (`conjuncion`, bloques) | `App.i18n.locale() === 'en' ? ' and $1' : ' y $1'` | Mapa por idioma, o clave en `strings.js` (`conjuncionY: ' y $1'`) |
| `tools/monedero/app.js:54` | `App.i18n.locale() === 'en' ? '.' : ','` (mismo patrón de separador decimal) | Igual que `numeros` |
| `tools/monedero/app.js:125` | Segunda aparición del mismo ternario | Igual que arriba |
| `site/index.html:23-24` (botones) + `:243-244` (`pintarSelectorIdioma`) + `:255,258` (listeners) | 2 botones de idioma fijos en el HTML, cableados a mano | Añadir un tercer `<button>` + su línea en `pintarSelectorIdioma()` + su `addEventListener` |

Todo lo demás (`register`, `t`, `pick`, `apply`, `detectar`, `locale`, `setLocale`)
ya es genérico sobre `SOPORTADOS` y no necesita tocarse.

## 5. Receta: añadir un idioma nuevo (ejemplo: francés, `fr`)

Ejecutar en este orden. Cada paso es mecánico salvo el 5 (contenido) y el 6 (números/horas).

### Paso 1 — Registrar el idioma en el núcleo

En `assets/js/i18n.js`:

```js
var SOPORTADOS = ['es', 'en', 'fr'];
```

Añadir `fr` al diccionario `core`/`feedback` (mismas claves que `es`/`en`, §1.2):

```js
fr: {
  core: {
    back: '← Retour', backToMenu: 'Retour au menu', playAgain: 'Rejouer',
    next: 'Suivant →', listen: '🔊 Écouter',
    listenInstructions: 'Écouter les instructions', listenText: 'Écouter le texte',
    loading: 'Chargement…', roundComplete: 'Manche terminée !'
  },
  feedback: {
    success: ['Bravo !', 'Génial !', "Tu l'as fait !"],
    encourage: ['Presque. Essaie encore !', 'Pas grave. Encore une fois !']
  }
}
```

Generalizar `lang()` (hoy binario, ver §4):

```js
var BCP47 = { es: 'es-ES', en: 'en-US', fr: 'fr-FR' };
function lang() { return BCP47[locale()] || BCP47[POR_DEFECTO]; }
```

Comprobar que el navegador/SO tiene una voz `fr-FR` instalada para `speechSynthesis`
(si no la hay, `App.tts.speak()` no falla, pero suena con la voz por defecto — avisar
al usuario si esto importa).

### Paso 2 — Selector de idioma en la landing

En `site/index.html`, añadir un tercer botón dentro de `.idioma-selector`:

```html
<button type="button" class="btn-idioma" id="btnIdiomaFr" data-locale="fr" aria-pressed="false">🇫🇷 Français</button>
```

y en el `<script>` de la misma página: añadir su línea en `pintarSelectorIdioma()`
(`aria-pressed`) y su `addEventListener('click', () => App.i18n.setLocale('fr'))`,
siguiendo el patrón de los botones ES/EN existentes.

### Paso 3 — Landing: `site/strings.js`

Añadir el bloque `fr: {...}` con las mismas claves que `es`/`en` en ese archivo.

### Paso 4 — Cada `tools/<slug>/strings.js` (30 archivos)

Añadir un bloque `fr: {...}` con **exactamente las mismas claves** que `es`/`en`
(mismos nombres, misma estructura anidada). Esto es mecánico pero tedioso — usar el
script de verificación de paridad del Paso 7 para no dejarse ninguna.

### Paso 5 — Cada `tools/<slug>/data.js` que duplica por idioma

Buscar los archivos que indexan `DATA` por locale:

```bash
grep -rln "\[App\.i18n\.locale()\]" tools/*/app.js
```

En cada uno, el `data.js` correspondiente tiene una clave `es`/`en` a nivel de
array u objeto (`DATA.lecturas`, `DATA.medidas`, `DATA.words`, `DATA.lessons`,
`DATA.placement`, `DATA.numpadSteps`, listas de historias/frases/chistes según la
herramienta…) — añadir la entrada `fr` con **al menos tantos elementos como
`DATA.porRonda`** (la mecánica de ronda, `sacar()`, baraja la lista pero no la
repite hasta agotarla; con menos ítems que preguntas por ronda se repetirían antes
de lo previsto). El orden entre idiomas no necesita coincidir uno a uno salvo que
el propio `app.js` de esa herramienta empareje elementos por posición (comprobar
caso por caso).

### Paso 6 — Formato específico del francés (números, horas, dinero)

No basta con traducir palabra por palabra (ver §2):

- **Números**: el francés también usa escala larga como el español (10⁹ = "milliard",
  10¹² = "billion" — ¡"billion" en francés es 10⁹, no 10¹² como en inglés ni como
  "billón" en español! Comprobar la tabla real de `DATA.lecturas` con cuidado,
  entrada por entrada, no reutilizar ninguna asunción de `es` ni de `en`).
- **Separadores**: francés usa espacio (o espacio fino) para miles y `,` para
  decimales (`1 234,50`) — no es ni el patrón español ni el inglés. Generalizar
  `separadorMiles()`/`separadorDecimal()` en `tools/numeros/app.js` (y el patrón
  gemelo en `tools/monedero/app.js`) a un mapa por idioma en vez del ternario actual.
- **Horas**: "trois heures et quart" / "quatre heures moins le quart" / "trois
  heures et demie" — de nuevo, ni la plantilla española ni la inglesa sirven de
  molde. Escribir las claves `horaEnPunto`/`horaYCuarto`/`horaYMedia`/
  `horaMenosCuarto` de `tools/reloj/strings.js` pensando en cómo lo diría un
  hablante nativo, no traduciendo la clave española.

### Paso 7 — Verificar paridad de claves antes de dar por hecho el idioma

Un `strings.js` al que le falta una clave en el idioma nuevo no rompe nada visible
(`t()` cae en silencio al español) pero deja texto a medias sin que se note en una
lectura rápida. Verificar con un script ad hoc por herramienta, por ejemplo:

```bash
node -e "
var fs = require('fs');
var App = { i18n: { register: function (d) { this.dict = d; } } };
new Function('App', fs.readFileSync('tools/parejas/strings.js', 'utf8'))(App);
function keys(o, p) {
  return Object.keys(o).flatMap(function (k) {
    var v = o[k], full = p ? p + '.' + k : k;
    return (v && typeof v === 'object' && !Array.isArray(v)) ? keys(v, full) : [full];
  });
}
var es = keys(App.i18n.dict.es), fr = keys(App.i18n.dict.fr || {});
console.log('faltan en fr:', es.filter(function (k) { return fr.indexOf(k) === -1; }));
"
```

(Adaptar la ruta del `strings.js` y repetir por herramienta, o generalizar el script
para recorrer `tools/*/strings.js` — es el mismo patrón usado para validar la
migración ES/EN, ver PLAN.md §9.1.)

### Paso 8 — Verificación funcional

- Landing: el tercer botón cambia todo el sitio y persiste en
  `localStorage['apptonomia:locale']`.
- Cada herramienta migrada carga sin errores de consola en el idioma nuevo
  (título, textos, audio con voz razonable si el navegador tiene esa voz).
- `numeros` y `reloj` en particular: leer en voz alta un par de preguntas de cada
  nivel y comprobar que el número/hora dicho es correcto, no solo que "suena a
  frase válida".
- `sw.js` no necesita cambios de contenido (los `strings.js` ya están en la lista
  de caché desde la Fase 6 de `PLAN.md`), pero **sí** hay que subir `VERSION`
  si se ha tocado cualquier archivo cacheado.

## 6. Qué NO hacer

- No dar por buena una traducción automática de números, fechas, horas o dinero sin
  comprobar la convención real del idioma (§2 y Paso 6).
- No dejar una clave sin su equivalente en todos los idiomas soportados — el
  fallback a español oculta el hueco en vez de fallar de forma visible.
- No usar arrays en `strings.js` para datos indexados por posición/número (`t()` los
  aplana con `join(', ')`); usar un objeto con claves de texto (`{0:'', 1:'...'}`).
- No añadir un idioma nuevo sin generalizar primero los puntos binarios `es`/`en`
  del §4 — si no, el idioma nuevo heredará en silencio el comportamiento inglés (o
  español) en formato de números/horas.
- No traducir literalmente dichos, chistes, adivinanzas o cualquier texto que
  dependa de un juego de palabras, una rima o una referencia cultural — escribir
  contenido propio del idioma destino con la misma dificultad e intención (§3).
  La traducción directa sí es correcta para vocabulario de objetos (`palabras`,
  `categorias`) y para situaciones/hechos universales (`situaciones`,
  `entre-amigos`) — la distinción es si el contenido depende del idioma en sí,
  no si "sale mejor" traducido.
- No dar por migrada una herramienta solo porque existe su `strings.js`:
  comprobar que `index.html` lo carga (`<script src="strings.js">`), que tiene
  atributos `data-i18n`/`data-i18n-aria`, y que `app.js` llama a `App.i18n` en
  algún punto. Los tres pueden faltar a la vez sin que se note a simple vista
  (ver el caso real de `tools/entre-amigos/` en §3).
